# Лабораторна робота №2. Протоколи IoT. MQTT

Козинець Назарій Ігорович, варіант №3. Виконання за спрощеною схемою з додатка до завдання.

## Запуск

Відкрийте термінал у цій папці та виконайте:

```powershell
npm.cmd ci
npm.cmd start
```

Редактор — [http://127.0.0.1:1880](http://127.0.0.1:1880), панель — [http://127.0.0.1:1880/ui](http://127.0.0.1:1880/ui).
У редакторі має з’явитися потік **Laba2**, на панелі — сторінка **Laboratory 2**, група **Laba2**.
Цей проєкт використовує власну папку налаштувань. Для запуску на порту 1880 завершіть інший процес Node-RED, якщо він уже працює.

Файл `Laba2_Козинець_3.json` також можна імпортувати в наявний Node-RED через **Import**. У цьому випадку встановіть `node-red-dashboard` та вимкніть потоки попередньої роботи перед **Deploy**.

## Підключення

Брокер **broker.hivemq.com**.
Node-RED використовує MQTT 3.1.1 через TCP, порт **1883**, QoS **1**, Retain вимкнено.
Для [вебклієнта HiveMQ](https://www.hivemq.com/demos/websocket-client/) установіть Host **broker.hivemq.com**, Port **8884**, SSL увімкнено.
На дату перевірки цей WebSocket-порт доступний. У двох вкладках задайте різні Client ID, наприклад `Kozynets3_A` і `Kozynets3_B`.

Власний ідентифікатор — `KozynetsNI3_20261123_c91e`.

| Призначення              | MQTT-тема                                           |
| ------------------------ | --------------------------------------------------- |
| Температура              | `IoTLab2/KozynetsNI3_20261123_c91e/Variant3/TT101`  |
| Клапан                   | `IoTLab2/KozynetsNI3_20261123_c91e/Variant3/Klapan` |
| Усі підтеми варіанта     | `IoTLab2/KozynetsNI3_20261123_c91e/Variant3/#`      |
| Клапани різних варіантів | `IoTLab2/KozynetsNI3_20261123_c91e/+/Klapan`        |

## Порядок перевірки

1. У клієнті B підпишіться на тему TT101, у A опублікуйте 10.5, 30, 75 і 50 через приблизно 5 секунд. QoS публікації та підписки — 1.
2. У A підпишіться на Klapan, із B опублікуйте 20, 40, 60 і 80.
3. Видаліть попередні підписки B. Підписка `Variant3/#` має отримати TT101 = 45 та Klapan = 70.
4. Залиште у B тільки підписку `+/Klapan`. Опублікуйте Klapan = 25, 50 і 75 для Variant1, Variant2 і Variant3. Публікація Variant2/TT101 = 90 не повинна надійти за цією підпискою.
5. Перевірте підписку `$SYS/broker/uptime`. Брокер може обмежувати системні теми.
6. На панелі Node-RED перемістіть повзунок. Температура надходить через брокер у вебклієнт, Debug та графік.
7. Із вебклієнта опублікуйте Klapan = 70, 20 і 90. Gauge має показувати відповідний відсоток.
8. Увімкніть «Генерація синусоїди» приблизно на дві хвилини. Не рухайте повзунок під час цього спостереження. Сигнал передається раз на 5 секунд у межах 25–75 °C, період близько 62,83 секунди.

Функції `ToNumber` і `Температура в число` відкидають порожні та нечислові повідомлення. Генератор синусоїди початково вимкнений, його стан задає перемикач Dashboard.
